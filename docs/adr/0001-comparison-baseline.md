# ADR-0001 — 비교선 수립: 누수 없는 자체 데이터셋 + KoBERT 재현

- **상태**: 수용
- **참조**: `PROJECT.md` 「평가 프로토콜」·「Hard boundary」, `docs/experiments/kobert-baseline.md`, `docs/data/data.md`

## 맥락

공식 baseline은 weighted-F1 **0.8249**를 보고한다. 이 숫자를 개선의 절대 기준으로 삼는 것이 가장 단순한 경로였으나, 두 결함이 있다.

1. **평가 방식 불일치.** 0.8249는 훈련은 멀티레이블(Focal=BCE 기반)이나 **평가는 top-1**(`argmax` 1개)을 단일화한 정답과 sklearn으로 잰 값이다(full test 24,525건의 weighted-F1). 이 프로젝트의 주 지표는 **멀티라벨 micro-F1**이라 축이 다르다.
2. **데이터 누수 위험.** 제공된 `Training`/`Validation` 분할은 **`documentId` 7,822개가 양쪽에 겹친다.** 같은 특허가 train·val에 동시에 존재하면 성능이 부풀려져 비교선으로 쓸 수 없다. 또 보고된 `300,240`은 고유 문서가 아니라 (문서,레이블) 쌍 수이며, 로컬 스냅샷은 고유 224,328건으로 다르다.

## 결정

공식 0.8249를 절대 기준으로 쓰지 않는다. 대신:

- **누수 없는 데이터셋을 재생성**한다 — 전체를 `documentId`(고유 특허) 단위로 집계한 뒤 재분할(train 201,895 / val 11,162 / **test 11,271 고정**).
- **KoBERT baseline을 그 고정 test 위에서 직접 재현**해 비교선을 세운다(0.8249 숫자를 옮겨 쓰지 않는다).
- **주 비교 지표 = 멀티라벨 micro-F1**(τ=0.5). top-1 weighted-F1·P@k는 벤더 연속성 앵커로 병기하되 개선 판정 기준이 아니다.

## 근거

- 누수·집계 단위·평가 축이 각각 독립적으로 0.8249를 비교 부적격으로 만든다 — 하나만 고쳐선 부족하다.
- 자체 재현선은 **같은 test·같은 코드 경로**에서 재현돼, 이후 모든 모델(A.X-Encoder 계열)이 동일 조건에서 겨뤄진다. 비교의 내적 타당성이 벤더 숫자와의 외적 대조보다 우선한다.

## 검토한 대안

- **0.8249를 그대로 기준으로 사용** — 기각. 누수·축 불일치로 개선분이 데이터 아티팩트와 분리되지 않는다.
- **공식 분할 유지 + 누수만 무시** — 기각. 7,822건 겹침이 val 성능을 낙관 편향시킨다.

## 결과·영향

- 이후 모든 실험이 고정 test 11,271과 KoBERT 재현선(멀티라벨 micro **0.8502** / 앵커 top-1 weighted **0.8148**) 위에서 비교된다.
- KoBERT 재현 macro가 원본(0.8038) 아래(0.7870)로 내려간 것도 이 재현 과정에서 드러났고, 이는 이후 A.X-Encoder의 macro 반전(→0.8648)을 해석하는 기준이 됐다.
- **한계**: 재현선은 공식 숫자와 직접 비교되지 않는다(다른 test set). 외부 벤치마크 대비 절대 우위 주장은 하지 않고, 통제된 내적 개선만 주장한다.
