# ADR-0011 — 자원 제약 하 실험 방법론: 단일 시드 + 노트북 중심 코드 관리

- **상태**: 수용 (진행 중 — 코드 성숙 단계 전환으로 src 리팩터 착수 예정)
- **참조**: `docs/experiments/modernbert-comparison.md`(잡음 하한·bin 단조 signature·2경로 교차확인 SSOT), `docs/experiments/loss-function.md`「부수 확인」·`docs/experiments/modernbert-results.md`「clean-data 512 실측」(레시피 정합 실측), 노트북 `../../notebook/08_01_ModernBERT_Recipe_lr1e4.ipynb`·`08_02_ModernBERT_Recipe_lr5e4.ipynb`(lr 프로브)·`11_01_CleanData_Recipe.ipynb`(풀런), `docs/infra/colab-jobs.md`·`docs/infra/runpod-jobs.md`(훈련 실행 경로), `../../CLAUDE.md`「노트북 중심」·「로컬 CPU 전용」, `src/error_analysis.py`

## 맥락

검증 신뢰성 축의 통상 기대는 두 가지다 — **시드 여러 개의 분산·신뢰구간**으로 개선이 잡음보다 큰지 보이는 것, 그리고 **클론 후 한두 커맨드로 재현**되는 코드 구조. 이 프로젝트는 둘 다 표준 형태로 충족하지 않는다. 그 선택이 태만이 아니라 자원 제약에 대한 배분 판단임을 기록한다.

두 제약이 근원이다.

- **로컬 GPU 부재.** 개발 머신은 Windows CPU 전용이라 훈련 코드를 로컬에서 실행·테스트할 수 없다. 훈련은 외부 잡(Colab L4 / RunPod)에서만 검증된다.
- **개인 프로젝트 예산.** 초기 레시피(L4, batch=8, len8192)에서 1런이 10~29시간이다. 헤드라인 실험만 시드 3~5개로 반복하면 수십~150시간 규모이며, 개인 예산에서 반복이 사실상 불가능하다.

## 결정

**두 방법론 결정을 자원 배분으로 확정한다.**

1. **단일 시드(seed 42)로 실험한다.** 개선 판정은 시드 분산이 아니라 **예측 signature 정합**(bin 단조성·2경로 교차확인·잡음 하한 실측)으로 방어한다.
2. **코드는 노트북 중심으로 관리하고, 로컬에서 반복되는 작업만 src로 추출한다.** 코드 성숙 단계(RunPod GPU 훈련 안정화)에 진입한 시점에 src 리팩터를 착수하고, 노트북은 JupyterLab 접속 후 실행 결과 기록용으로 역할을 재정의한다.
3. **레시피(배치·lr)는 짧은 프로브로 좁히되, 스케줄과 horizon의 결합을 판정에 반영한다.** eff_batch·lr 조합은 조합마다 12에폭 풀런을 돌리는 대신 2에폭 SEARCH 프로브(`08_01` lr 1.2e-4=sqrt / `08_02` lr 4.8e-4=linear, eff128)로 좁힌다. 다만 고정-에폭 프로브의 lr 서열은 배포 horizon으로 그대로 전이되지 않으며, lr 선택은 프로브 승패가 아니라 스텝 예산 보존으로 정당화한다(아래 근거).

## 근거

- **단일 시드 — 비용 배분.** 1런 10~29시간에서 멀티시드는 헤드라인 결론의 자원 배분으로 비합리적이다(자원 배분이 문제 중요도에 비례해야 한다는 기준에서, 여기에 컴퓨트 3~5배를 쓰는 것은 틀린 배분이다). 대신 결론을 다음으로 방어한다:
  - **예측 signature 정합.** 창 확장 효과가 길이 bin에서 단조 증가(exp1−exp2 micro Δ: B0 +0.46 → B3 +2.64pt)해 truncation 회복이라는 사전 예측과 일치한다. 시드 반복이 아니라 기제가 예측한 방향·기울기로 신호를 확증한다.
  - **2경로 교차확인.** 같은 분해를 집계 지표(micro-F1)와 문서 단위 앵커 오류 차집합으로 독립적으로 세워 같은 결론에 도달한다(`modernbert-comparison.md` 「오류 수준 재현」).
  - **잡음 하한 실측·명시.** 절단이 없어 창 확장이 벌 것이 없는 B0에서 순이득 −15건(B0 3,197건의 −0.5%p)을 **별개 훈련 런 사이 잡음 규모의 실측 하한**으로 삼고, 나머지 bin의 이득이 그 수준을 넘음을 보인다. "단일 런 쌍이므로 통계적 검정은 아니다"를 병기한다.
- **노트북 중심 — 제약 적응·이식성.** 훈련 코드가 로컬에서 실행 불가라 로컬 개발 → 외부 잡 디버깅으로 코드가 흩어진다. `notebook/`(작성)과 `notebook_output/`(외부 실행 결과) 분리가 이 워크플로의 산물이다. 반복 로컬 작업(오류 분석)만 `src/error_analysis.py`로 추출하고, 나머지는 Colab·도커로 **이식이 쉬운 노트북**으로 둔다. 셀 실행 순서 의존은 **아티팩트 기반 인계**로 완화한다 — 각 노트북이 저장된 로짓·지표(`output/*.npy`·`*.json`)를 읽어 재훈련 없이 하류 분석을 재계산하므로, 인계가 셀 순서가 아니라 고정 아티팩트로 이뤄진다.
- **조기 추상화 회피.** GPU 없는 로컬에서 훈련 코드를 반복 실행할 수 없는 단계에서 src 패키지화를 먼저 하면, 검증되지 않은 코드에 추상화 비용만 든다. 코드가 외부 잡에서 안정화된 뒤 추출하는 편이 배분에 맞는다.
- **짧은 프로브 — 예산 적응과 그 함정.** 조합마다 12에폭(런당 수 시간)을 돌리는 대신 2에폭 프로브로 후보를 좁히는 것은 배분에 맞는다. 그러나 `linear` 스케줄 + `warmup_ratio` + decay-to-zero는 **총 스텝에 묶여(horizon-coupled)** 프로브의 lr 서열을 왜곡한다:
  - **고정-에폭·삼각 감쇠에서 진행량 ∝ ∫lr dt ∝ peak lr** — 발산 임계 아래면 높은 lr이 짧은 창에서 항상 앞선다. 프로브의 편향 방향(고lr 우대)이 결과(4.8e-4가 1.2e-4를 전 구간 상회)와 같은 쪽이라, 이 프로브는 linear vs sqrt를 **판별하지 못한다**(같은 방향 편향과 겹친 결과는 정보가 없다).
  - warmup 비중(2에폭 프로브 0.2 vs 12에폭 풀런 1.2 에폭)과 감쇠 기울기가 달라, 풀런은 뜨거운 lr을 훨씬 오래 유지한다. 프로브의 급감쇠가 이 지속 노출을 가린다 — 같은 에폭 지점이 lr 궤적에서 다른 자리다.
  - **프로브가 실제로 준 것**: 4.8e-4가 eff128에서 발산하지 않고 건강히 학습된다는 안정성·충분성 확인. lr 서열이 아니라 이 사실로 읽는다.
  - **전이 가능한 lr 판정법**: horizon과 분리한 프로브 — constant-lr(또는 warmup→constant) 고정-스텝 비교, 또는 LR-range test — 를 쓴다. 고정-에폭 linear-decay를 end-of-probe F1로 판정하지 않는다.

## 검토한 대안

- **헤드라인 실험만 멀티시드.** 미채택(비용). 다만 이보다 값싼 표적이 있다 — 오차막대가 필요한 것은 헤드라인 절대값이 아니라 **길이(+0.84pt) vs 모델(+0.99pt) 분해**이고, 분해의 저비용 끝은 512 계열이다. 512 재현 1런으로 exp1−exp2·exp2−KoBERT 두 델타에 run-to-run 변동 하한을 직접 붙일 수 있다 — 아래 「결과·영향」에 집행 결과를 기록한다.
- **처음부터 src 패키지화.** 미채택(위 「조기 추상화 회피」). 코드 성숙 전 추상화는 이식성만 해친다.
- **더 큰 배치·짧은 런으로 멀티시드 예산 확보.** 부분 채택. 레시피 확정(`08_01`/`08_02`)으로 eff_batch를 128까지 올렸으나(L4→A40), 이는 손실 실험 비용을 낮추려는 것이지 시드 반복 예산을 만들려는 것이 아니다. 시드 배분 결론은 불변.
- **조합마다 12에폭 풀런으로 lr 선택.** 미채택(비용). horizon-faithful하나 조합 수 × 수 시간이라 배분 불가다. 대안은 위 근거의 horizon-분리 프로브 — 짧은 예산을 유지하면서 서열 전이성을 회복한다.

## 결과·영향

- **신뢰 상한이 잔존하나 제약 하 근접-최적으로 완화된다.** 분해 델타에 신뢰구간이 없다는 점은 남는 공백이며, 통제 길이효과 +0.84pt가 잡음 하한 ~0.5pt와 가까워 여백이 넓지 않다. signature 정합·2경로 교차확인이 이를 정성적으로 보강하나 CI를 대체하지는 않는다 — 이는 역량 결함이 아니라 이 증거 두께의 성질로 서술한다.
- **값싼 레버 집행 완료 — 단일 시드 선택이 실측으로 방어된다.** 대상은 exp2가 아니라 현행 레시피 `11_01`이다(손실 축 기준선을 겸해 회수량이 크다). `11_04`(seed 153)가 시드 외 전 설정을 고정하고 돌아, 시드 쌍의 paired bootstrap까지 집행했다([eval-noise.md](../experiments/eval-noise.md)):
  - **훈련 잡음이 평가 표본 잡음 바닥 아래다.** 시드 델타 micro −0.18pt는 구간 [−0.55, +0.21]로 0을 포함하고, `D² < σ_표본²`이라 훈련 성분이 분해되지 않는다. 관측 |Δ| 0.176pt는 σ_훈련=0일 때 표본 잡음만으로 기대되는 0.157pt와 사실상 같다. **12 epoch 완주 지점에 한해, 시드 반복 없이 표본 구간만으로 판정해도 결론이 바뀌지 않는다** — 이 ADR이 감수한 위험이 이 레시피에서 작다.
  - **분해 축이 확정된다.** 길이(+0.84pt)·모델(+0.99pt) 두 델타는 넓힐 근거가 없는 표본 구간에서 0을 배제한다. 위 「신뢰 상한」이 우려한 "여백이 넓지 않다"가 해소됐다.
  - **대가는 focal−BCE다.** 시드를 바꿔 다시 재니 +0.52pt → +0.34pt로 줄며 유의성을 잃는다. 분산 추정이 아니라 **직접 재측정**이 잡아낸 취약성이다. 운영 판정선: micro 델타 **0.6pt 미만은 시드 1런씩으로 확정하지 않는다**.
  - **자유도 1의 한계는 남는다.** "σ_훈련 = 0"이 아니라 "이 test로는 보이지 않는다"이며, 다른 레시피(eff_batch 8 계열)나 수렴 이전 지점으로 옮길 근거는 없다. 시드를 더 늘리는 것은 여전히 배분에 맞지 않고, 위 판정선을 쓰는 편이 값싸다.
- **코드 성숙 전환**: RunPod GPU 훈련 착수로 훈련 경로가 안정화됐다 → 반복 안정화된 코드를 src로 리팩터하고, 노트북은 결과 기록용으로 역할을 좁힌다. 아티팩트 기반 인계(`output/*`)는 전환 후에도 하류 분석의 재현 축으로 유지한다.
- **linear 스케일 채택은 프로브가 아니라 스텝 예산 보존으로 정당화된다.** eff_batch 16배 상향은 스텝을 16배 줄인다. linear(4.8e-4)는 총 최적화 예산(스텝×lr ≈ exp2 9.1)을 보존하나 sqrt(1.2e-4)는 그 1/4이라 12에폭에서 undertrain 위험이 있다. `11_01`(linear, 12에폭)이 test micro 0.8588로 exp2(0.8601)와 잡음 내 동률에 안착해 예산 보존을 실측 확인한다(「clean-data 512 실측」·「부수 확인」). "Adam엔 sqrt" 격언은 에폭 고정 시 per-step 노이즈 정합을 겨냥한 것이라 스텝 컷을 반영하지 않는다.
- **미측정으로 남는 것**: sqrt(1.2e-4) 12에폭 풀런. 기대 방향이 undertrain으로 애매해(더 낮을 수도 있어) 성능 레버로서 우선순위가 낮다 — 궁금증 해소용 확인 런이지 개선 후보가 아니다.
